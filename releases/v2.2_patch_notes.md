# Dev Patrika Release Notes — v2.2-patch

**Release Date**: September 07, 2026  
**Scope**: RAG Chatbot Refinement, Multi-Model Selection Sync, Extended Memory Window, and Server Availability Optimizations.

---

## 🚀 Key Improvements & Updates

### 1. RAG Chatbot (`devBot`) Multi-Source Refinement
* **GitHub Radar Integration**: Refined `stream_chat_message` context retrieval in [`Backend/app/services/chat/chat_service.py`](file:///d:/Dev-Patrika/Backend/app/services/chat/chat_service.py) to query **GitHub Radar trending repositories** alongside `wiki_entries` and `news_items`.
* **Dynamic Threshold Fallback**: Configured semantic vector search to query at similarity threshold `0.25` with an automatic fallback threshold `0.15` for queries with non-exact vocabulary, ensuring context is never empty.
* **Resilient LLM Failover**: Wrapped model streaming execution in an automated failover block to failover to `gemini-2.5-flash` instantly if primary model initialization encounters rate limits or network glitches.

### 2. Conversational Memory Expansion
* **20-Message Window**: Expanded the persistent conversation memory sliding window in Neon Postgres from 10 to **20 messages (10 complete Q&A turns)**.
* Enables users to ask multi-turn cross-questions without losing context of previous news discussions.

### 3. Model Selection State Sync Fix
* **Active Groq Model Verification**: Live-tested Groq API key models and updated model selection to route to **`openai/gpt-oss-120b`** (100% active on Groq API), fixing the 404 `model_not_found` error.
* **Frontend State Alignment**: Updated [`chatStore.js`](file:///d:/Dev-Patrika/Frontend/src/store/chatStore.js) and [`FloatingChat.jsx`](file:///d:/Dev-Patrika/Frontend/src/components/layout/FloatingChat.jsx) to set the initial default model to `gemini-2.5-flash` and auto-sync Zustand state with `/api/ai/models` when fetched.

### 4. Server Liveness & HEAD Request Support
* **HEAD API Support**: Configured `/health`, `/api/health`, and `/` endpoints in [`main.py`](file:///d:/Dev-Patrika/Backend/app/main.py) and [`health.py`](file:///d:/Dev-Patrika/Backend/app/routers/health.py) to explicitly accept `HEAD` HTTP method requests.
* Allows 7-8 minute uptime ping bots to keep Render free tier web service active 24/7 with 0 MB payload overhead.
